# Tc26 Rust verification view

Open `Cargo.toml` in your IDE. `src/lib.rs` is the actual source
translated by Charon and Aeneas. It is not generated by Python.

The two cipher methods preserve the original RustCrypto `for` loops,
iteration bounds, round expressions, and block output operations.
Comments show the upstream code. The S-box source is imported
directly via `#[path = "../../magma/src/sboxes.rs"]`.

Two changes are explicitly allowed within each method body:
- `S::g` → `sboxes::Tc26::g`: specialize the generic S-box.
- `let b = block.get_in()` → `let b = block.get_in().bytes`:
  copy eight bytes before the loop to avoid an Aeneas borrow-analysis bug.

`scripts/check-tc26-source.py` compares both method bodies with upstream
and fails if any other differences appear. No round is unrolled.

The `Block`/`InOut` adapter is verification-only. Its equivalence to
the actual `cipher` types has not been proved.

```sh
../../scripts/setup-rustcrypto.sh
cargo check --locked
cargo test --locked
cargo fmt --all --check
```

Tests compare with original `magma::Magma` on 256 deterministic
key/block pairs and verify an RFC 8891 vector.
